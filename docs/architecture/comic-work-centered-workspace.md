# 以作品为中心的 Comic 创作工作区

2026-10-16。本页描述新建作品入口的当前契约；旧对话的逐 Brief 制作链路继续兼容读取，不能用旧聊天身份替代新作品身份。

## 身份与存储

- 作品容器复用父 Comic Project；每条新创作生成一个子制作 Project。任务 ID 就是子 Project ID，导演稿、确认、指令、图片、素材和版本分别属于子 Project。
- `workspace_work`、`workspace_task`、`workspace_request`、公共设定来源及历史导入日志均追加到既有 `comic_entity_versions`。没有新增业务表。
- 作品持有一个用户连续对话和一个独立内部故事锚点，均复用 Core Conversation。新方案绑定用户对话；旧作品保留原任务对话并在作品对话中聚合读取，消息 ID、原 Run 和原始记录不改写。作品故事 ID 由作品 ID 派生。
- 侧栏复用原 ConversationHistory，平铺一作品一行，提供搜索、重命名和删除。删除追加 `workspace_work.deleted_at`，不删除子 Project、Conversation、Run 或产物。
- 前三步按任务读取制作 Project；故事与导出按作品读取同一 Story 快照。新故事、导出 URL 只携带作品 ID。非法任务归属失败时清空当前选择，不回退最近方案。

## 执行与多轮上下文

组织服务是 `domains/comic/workspace.py::ComicWorkspaceService`；Shell 组装既有 Director、Context、Compiler、Media、Story 和 Core Runtime。

`POST /api/comic/works/{work}/turns` 使用作品对话、父作品预期版本及唯一 request_id。共享 ConversationContext 定位本轮目标与有来源设定；普通新创作（包括动作续写）以 create 建立独立 Project。只有明确修改某份方案或 `turn_operation=revise` 才更新目标方案，并核验所属作品与目标版本；目标不明则澄清。图片分析/改图继续使用选中图片及真实任务归属。原 task turns 接口保留旧客户端兼容，新客户端不再调用它决定方案隔离。

讨论保存消息，不修改导演版本。每轮输入与原 Coordinator 共用消息身份，不按文字去重。来源目录限当前作品成员；选中来源的稳定人物/场景/风格进入本轮上下文，旧混合段落中的动作、表情和构图交由本轮重新组织；明确引用的叶子字段和固定资产约束继续保护。后台结果保存到发送时绑定的 Project，前端拒绝晚到结果切换当前选择。

`GET /api/comic/works/{work}/conversation` 返回持久化消息与成员 Run；`GET .../requests/{request_id}` 查询原认领结果。返回明确的消息、Run、任务与版本关联。原请求重放恢复原结果；已提交而结果未绑定时不自动重发。前端按作品保存待核对请求，刷新仅查询。消息入口选择准确 Run/版本，旧稿不会被当前最新稿替换。直接方案编辑、Compiler、人工确认及生产历史继续复用原协议。

每个新方案都属于 FIRST_GENERATION/NEW_CONTEXT，不因轮次、context_changes 或继承人工编辑来源而改为 USER_EDIT。原 Coordinator 检查约束、人物与场景、动作构图、摄影完整性及节点矛盾，执行已有一次有界修正后再校验完整内容。阶段失败、修正失败或内部校验不可用均为未完成；作品新方案只将候选保存在 Run，不更新当前导演指针，接口 validation.can_confirm=false。人工确认入口同样阻止绕过。首次生成显示“方案检查”，主动编辑保留公开导演审核。

## 公共设定

作品角色、场景、风格的可选引用继续使用现有 Asset Store。新创作不会自动复制全部公共资产；显式采用后记录公共来源版本、本地资产 ID/版本。局部编辑在方案内；只有“更新作品设定”才发布公共新版，或显式采用某个任务内资产版本。

其他画面显示可更新提示，用户选择同步后生成新的本地资产和绑定修订。已有资产修订、旧图、采用版本和故事固定引用保持原身份。新增参考 Artifact 必须属于该作品成员任务。模型创作选择不会自动发布为公共设定。

## 故事与导出

`/api/comic/works/{work}/story` 及其 images、versions、requests、save、generate、review、confirm、restore、adopt-candidate、exports 操作复用既有 Story 服务。服务端固定父作品锚点，拒绝客户端指定其他作品或内部对话。

候选仅汇总成员任务实际采用的版本；每个镜头固定图片、版本、Artifact 和哈希。不同人物不会因同作品而自动合并身份。故事保存、生成候选、核验、确认及导出继续沿用内容指纹、CAS、请求认领与历史修订。导出先核验图片，再用标准库 ZIP 原子写入 Core DOCUMENT Artifact；不会调用模型。

## 共享图片显示

`imageViewport.ts` 提供适应大小、缩放和偏移限制；`ImageViewport.vue` 用于版本对比和故事/导出大图。图片工作台的选区层使用同一几何函数。

适应大小为最小缩放，能完整显示时居中。放大后每轴偏移限制为放大尺寸与显示区尺寸之差的一半。滚轮围绕鼠标位置缩放；缩放、拖动、定位、重置、换图和窗口变化均限制边界。固定显示区裁剪放大后的图片，不出现独立白色相框；查看操作不改写归一化选区。缩略图保持静态。

分析页面分别展示尚未分析、执行失败、分析完成且无明确偏差，以及真实建议/限制。空 findings 不会伪造修改建议。

## 历史归入

`GET /api/comic/works/legacy-preview` 根据原 Project、Brief、Run、图片及故事引用生成带指纹的来源预览，不依据标题相似合并。弹窗内明确勾选来源；不确定的消息留在原对话。

`POST /api/comic/works/legacy-import` 在写入前通过 DatabaseManager 执行 SQLite 一致性备份。原请求与冻结预览、各步骤预期版本及结果保存在既有修订表，支持相同请求重放和中断恢复。导入追加新父作品、任务、任务对话、资产/导演草稿和原始图片版本；新旧身份保留映射。图片通过既有 Media 导入，原字节与采用来源保留。

原聊天、原 Director/Compiler/Artifact 历史不移动或删除。任务提供原方案、Prompt 和图片历史链接；旧 Prompt 不伪装成新任务 Compiler 产物。导入故事使用新图片身份并保留原图约束来源，初始为待核验草稿，旧身份下的确认不复用。导入本身没有模型调用。

### 本次覆盖问题的定向恢复

`POST /api/comic/works/{work}/recover-plans` 接收明确的 source_run_groups 和预期作品版本，复用原导入、版本存储及 Core Run。写入前执行 SQLite 一致性备份；逐步记录来源、恢复 Project、Run、版本和备份，支持中断后沿原请求继续。版本不确定、重复或顺序不合法直接拒绝。原任务保留为 history_source_only，故事固定引用不变；对话投影映射消息入口，原消息绑定不改写。恢复副本清除旧确认，不声称已重新通过内部检查。
