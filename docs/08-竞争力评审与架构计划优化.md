> 本文基于 2026-09 的岗位 JD、行业报告与上游项目现状，对 docs/01–07 做一次外部视角评审。

> 结论一句话：**原方案工程素养很高，但"底座选型 + 六周节奏 + 框架禁令"这三个决定，会把一个能打的项目拖成不能交付的烂尾。**

## A · 可用性诊断（能不能做完）

### 🔴 P0：三个会致命的决定

**R1 · 底座 Open-LLM-VTuber 正在 v2.0 全量重写，v1 已 feature-frozen**

- 事实：官方 README 明确写着 —— "We are focusing on Open-LLM-VTuber **v2.0 — a complete rewrite of the codebase**. v2.0 is in early discussion and planning phase… **refrain from opening new issues or PRs for feature requests on v1**." 同时长期记忆功能已被临时移除（`long-term memory feature is temporarily removed`）。
- 影响：你让 M0 = "跑通底座"，等于把项目的第一步压在一个**即将被重写**的上游身上。Windows 上 ASR（sherpa-onnx / FunASR）+ ffmpeg + 回声消除 + Live2D 是著名的三天坑，新手实际 1.5–2 周很常见。更糟的是——**底座跑不跑得通，和你简历的核心资产（工具调用/预算治理/质检/评测）毫无关系**。
- 决策：**把底座从"前置依赖"降级为"可插拔交互外壳"，挪到最后。** 主线先做 headless 内核（CLI），M9 再接 VTuber。接不上去也不影响任何里程碑验收。

**R2 · 六周 / 120–180h 总预算，严重低估**

- 你自报 20–30h/周，六周 = 120–180h。要塞进：M0 底座 + M1 分镜 + M2 生图 + M3 质检 + M4 记忆检索 + 兼职周 0。新手真实系数是**估时的 1.5–2 倍**（API 调试、标注集制作、演示录制都会被低估）。
- 其中两个隐性巨坑：① M3 要"人工标注 50 张"——光标注就要 3–4h；② 每个里程碑都要录 1 分钟演示——录制 + 剪辑 + 补拍，一次 2h 起。
- 决策：**主线拉到 10 周（≈245h）**，每个里程碑拆 **MVP 档 / 增强档**，来不及只交 MVP，里程碑不算失败。

**R3 · "明确不做：多 Agent 框架（LangGraph/AutoGen 等）" 与求职主线直接冲突**

- 事实：2026 年 Agent 岗 JD 几乎条条都写 LangGraph / LangChain / AgentScope / PydanticAI / CrewAI，且要求"**理解其底层运行机制**"（不是"用过"）。你的 03 文档把这条路主动封死了。
- 但你的初心是对的：**手写 function calling 内核比调包有深度得多，面试能讲到底层**。错的只是执行方式——"不用框架" ≠ "简历上不出现这个词"。
- 决策：**手写内核 + 显式对标，两头都要**：
  1. 保持手写 Tool Calling 内核（差异化，不动）；
  2. 新增 `agent/graph.py`：约 100 行显式状态机（节点 / 边 / 状态 / checkpoint）；
  3. 新增 `docs/langgraph-mapping.md`：写清本模块与 LangGraph `StateGraph` / `Checkpointer` 的概念映射表。
  - 效果：简历可以写"手写 Agent 状态机，与 LangGraph StateGraph 概念对齐并给出映射"——这比"用过 LangGraph"**更强**。
  - M8 可选再加一个"同一组工具用 LangGraph 重写"的对比分支（1–2 天），是极强的面试素材。

### 🟡 P1：四个结构性问题

**R4 · 缺 2026 三大热点关键词**

| 热点 | 现状 | 你的方案 |
|---|---|---|
| **MCP** | 已成事实标准（2026-07-28 规范改版，无状态化，被称"AI 的 USB-C"）。阿里/滴滴/中控 JD 全在写 | 加一层皮：把已有工具用 MCP Python SDK 暴露成 server（≈100 行）。**同一份工具函数既能给你自己的 loop 用，也能给 Claude Code / Cursor 用**——"一次实现两处可用"本身就是 2026 最香的叙事 |
| **Context Engineering** | Gartner 定调 "context engineering is in, prompt engineering is out"；JPM 2026 报告把"从提示工程转向上下文工程"列为核心趋势 | 你的 03 里还叫"Prompt 工厂"。改名 + 加一层：拼 prompt 前做上下文预算裁剪（只喂当前镜号相关的角色卡/历史，不灌全量）。这是面试能讲出花的地方 |
| **可观测性 / Tracing** | JD 反复出现："日志、指标、Tracing 和告警体系""Token 消耗、响应延迟、成功率及异常原因" | 加 `core/tracing.py`：每次 LLM/工具调用落一条 trace（耗时/token/费用/成功与否），评测报告与成本报告都从 trace 生成 |

**R5 · 质检"一致率 ≥85%"是个不可控指标**

- "人设跑偏"是主观项，VLM 打分与人工一致率 85% 很难稳定达成，新手极易在这里卡死一周还调不出数字。
- 决策：**拆成 3 个二元判定（崩手 / 水印 / 构图严重异常）+ 1 个人设一致性 5 分制打分**。
  验收改为：**二元项与人工一致率 ≥90%；打分项与人工分差 ≤1.5 分**。
  先建 30 张标注集跑出基线，**再用基线反推阈值**，不要先定阈值再倒逼模型。

**R6 · 兼职线定位（你选了"两者都要，以战代练"）**

- 2026 真实行情：承制价已跌到 **100–500 元/分钟**（2024 年是 1500），制作成本 30–80 元/分钟；爆款率约 **0.11%**，**90% 从业者亏损**，流量分成万播仅 5–30 元。
- 决策：**70% 精力接单代工（现金流 + 真实数据），30% 试账号**。
  关键设计：**把接单本身做成 Agent 的验收场景**——每接一单都跑一遍 Agent 流程并填 05 表，一份力气同时拿到「真实场景验证」+「简历量化数据」。
  红线：**兼职周工时上限 10h**，超出就砍接单，开发优先。

**R7 · 二次元人设在简历上是双刃剑**

- 风险：面试官可能读成"二次元玩具项目"，而不是背后那套工程。
- 决策：**叙事分层**——仓库和文档一律用专业工程语言；人设只作为"交互层设计"一章，并讲清产品理由（高频长时间使用时降低认知负荷、情绪价值提升留存率）。
  面试顺序：**先讲工程（工具调用 / 预算 / 评测），最后 30 秒放人设演示当记忆点**。

### 🟢 原方案做对的，必须保住

| 做对的 | 为什么稀缺 |
|---|---|
| 规范先行（01/02/03 的密度超过多数工作 3 年的人） | 面试问"你怎么保证质量"时，这是标准答案 |
| 预算控制器 + 成本台账 | JD 里"成本优化"是加分项，几乎没人有 |

| 双线咬合（兼职喂真实需求） | 你最强的差异化叙事，比任何技术点都值钱 |

## C · 架构 v2

### C1 · 四个核心改动

1. **交互层可插拔**：`InteractionShell` 协议 → `CLI`（默认，W1 起可用）→ `Gradio Web`（可选）→ `VTuber`（M9，接不上不影响）。
