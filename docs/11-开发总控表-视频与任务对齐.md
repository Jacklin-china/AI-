## 1 · 一条主线：数据是怎么流的

整个项目只有一条数据流，10 周全部围绕它：

```
剧本(文本)
  → [M1 分镜]    分镜 JSON 列表          shot 表
  → [M2 上下文]  按镜号裁剪 → 生图 prompt   （不入库，每次现算）
  → [M3 生图]    图片文件 + 台账           asset / ledger 表
  → [M4 质检]    质检 JSON                qc 表
  → [M5 记忆]    可检索的历史素材           persona / asset 表
  → [M6 状态机]  流程可中断可恢复           checkpoint 表
  → [M7 MCP]     同一批工具对外暴露         （无新表）
  → [M8 验收]    工时/成本对比报告          来自 ledger + trace
```

**每一跳都会落一条 trace**（W1 就建好），所以后期所有报告都是查表生成的，不是各写各的。

## 3 · 三个贯穿件（所有模块共用，先立规矩）

### 3.1 配置 `config.py`

```python
# setting.py —— 结构来自 config/settings.yaml，密钥来自环境变量
class LlmSettings(BaseModel):
    # 主力（文本 / 工具调用）：火山方舟 豆包 Seed 2.1 Turbo
    # 官方支持：工具调用 + 结构化输出(json_schema) + 多模态理解
    base_url: str = "https://ark.cn-beijing.volces.com/api/v3"
    model_chat: str = "doubao-seed-2-1-turbo-260628"
    api_key_env: str = "ARK_API_KEY"

    # 视觉位：豆包 turbo 支持多模态理解，可同一模型；纯文本模型不可填这里
    vision_base_url: str = "https://ark.cn-beijing.volces.com/api/v3"
    model_vision: str = "doubao-seed-2-1-turbo-260628"
    vision_api_key_env: str = "ARK_API_KEY"

    # 降级位：跨供应商才是真降级（主力不可用时自动切）
    fallback_base_url: str = "https://open.bigmodel.cn/api/paas/v4"
    fallback_model_chat: str = "glm-4.6"
```

> 铁律：**任何模型名、URL、金额都不许硬编码在业务代码里。** 全部走 `settings`。  
> 这是 W8 "MCP / 降级模型" 和 W4 "换生图供应商" 能一天完成的前提。  
>
> ⚠️ **上面代码里的值是"当前选定值 + 兜底默认值"，不是配置源。**
> 生效优先级：**`config/settings.yaml` 覆盖 类里的默认值**
> （`get_settings()` 里 `LlmSettings(**raw.get("llm", {}))` 就是在做覆盖）。
> 类里保留默认值只有一个目的：yaml 缺这个字段时仍能跑。
> **换模型 / 改地址 → 只改 yaml，不要改代码里的默认值**
> （01 §1：yaml 是配置结构的唯一事实来源）。
>
> ⚠️ **W1 步骤 6 必做**：去火山方舟控制台开通模型、核对 Model ID（版本号会变），  
> 并确认视觉能力是否需要单独型号——需要就只改 `model_vision` 一行。

### 3.2 LLM 客户端 `core/llm.py`

```python
def chat(messages: list[dict], *, model: str | None = None,
         response_format: dict | None = None,
         tools: list[dict] | None = None,
         trace_ctx: dict | None = None) -> Message:
    """一次 LLM 调用。内部做三件事：超时重试 → 落 trace → 返回 message 对象。"""
```

- 返回值是 **message 对象**（不是字符串），因为 W2 要读 `message.tool_calls`
- 超时/重试/降级全部读 `settings`，异常统一转 `LLMError`（挂在 `errors.py` 异常树上）
- **每次调用必须落一条 trace**——哪怕是失败的调用

### 3.3 埋点 `core/tracing.py`

```python
@dataclass
class Trace:
    ts: str            # 时间
    kind: str          # "llm" | "tool" | "image" | "qc"
    model: str | None
    in_tokens: int
    out_tokens: int
    latency_ms: int
    cost_cny: float
    ok: bool
    shot_no: int | None    # 能关联到镜号就关联，后期按镜号出成本报告
    error: str | None
```



> ⚠️ **W1 不建这张表，W8 的报告就出不来。** 这是全清单最容易烂尾的隐性依赖。

```python
class Shot(BaseModel):

    desc: str

    camera: str
    duration_s: int

    episode: str

# 解析失败必须能打印原始返回，这是排查的唯一线索
def parse_storyboard(raw: str) -> Storyboard:
    try:
```

```python
# agent/loop.py 骨架 —— 不许看资料，闭卷写，写完再对照视频
def run(user_msg: str, max_steps: int = 8) -> str:
    messages = [{"role": "system", "content": SYSTEM},
                {"role": "user", "content": user_msg}]
    for step in range(max_steps):
        msg = chat(messages, tools=registry.to_json_schema())
        if not msg.tool_calls:                     # 没有工具调用 = 说人话 = 结束
            return msg.content
        for call in msg.tool_calls:                # 逐个执行工具
            fn = registry.get(call.function.name)
            args = json.loads(call.function.arguments)
            result = fn(**args)                    # ← Pydantic 校验在这里生效
            messages.append({"role": "tool", "tool_call_id": call.id,
                             "content": json.dumps(result, ensure_ascii=False)})
    raise LLMError("超出最大步数，可能陷入循环")
```

### 7.1 `logging_setup.py`（步骤 3 最后一块）

**知识 3 分钟**

- 标准库 `logging` 配置繁琐（Handler / Formatter / Logger 三层），`loguru` 一个函数搞定
- **双通道**的含义：控制台只给人看（INFO 以上、带颜色），文件给排查用（DEBUG 全量、可回溯）
- 为什么必须"落文件"：W8 的 trace 报告、W4 的成本台账都要能事后查，终端一关就没了

**你要实现的契约**

```python
def setup_logging(level: str = "INFO") -> None:
    """初始化日志。level 从 settings.app.log_level 读，不硬编码。"""

# 其他模块统一这样用：
from loguru import logger
logger.debug("裁剪前 token={}", n_before)
```

**分步任务**（每步做完立刻自检）

| 步 | 做什么                                                                                                                     | 自检方法                                    |
| - | ----------------------------------------------------------------------------------------------------------------------- | --------------------------------------- |
| 1 | `logger.remove()` 清掉 loguru 默认 sink                                                                                     | 跑一次，控制台不再出现默认绿色格式                       |
| 2 | 加控制台 sink：`level=INFO`，带颜色，格式含 时间/级别/消息                                                                                 | 打 `logger.info("hi")` 能看到               |
| 3 | 加文件 sink：`level=DEBUG`，路径 `data/logs/kantoku_{time}.log`，`rotation="10 MB"`，`retention="7 days"`，**`encoding="utf-8"`** | 打 `logger.debug("secret")`→控制台不出现，文件里出现 |
| 4 | 接配置：`level` 从 `get_settings().app.log_level` 读                                                                          | 把 yaml 改成 DEBUG，重启后控制台也能看到 debug        |
| 5 | 在 `data/` 不存在时自动创建目录                                                                                                    | 删掉 `data/` 再跑，不报错                       |

**掉坑提示**（卡住再看）

- loguru 默认输出到 **stderr** 不是 stdout——管道重定向时别找错地方
- Windows 中文乱码 → 文件 sink 必须加 `encoding="utf-8"`
- `data/` 已被 `.gitignore` 忽略（正确），但代码里要 `mkdir(parents=True, exist_ok=True)`
- 别用 f-string 写日志，用 `logger.info("x={}", x)`——loguru 的惰性格式化能省性能

**过关自测**：关掉终端重开，能否从 `data/logs/` 里翻到上次的 DEBUG 记录？能 → 通过。

### 7.2 `core/llm.py`（步骤 4 · 第一次真实调模型）

**知识 3 分钟**

- OpenAI SDK 的 `OpenAI(base_url=..., api_key=...)` 能接任何 OpenAI 兼容端点（豆包/智谱/混元都是）
- `chat.completions.create()` 返回 3 层壳：`response.choices[0].message`
- **这次要返回 `message` 对象而不是 `.content`**——因为 W2 要读 `message.tool_calls`
- 超时重试不是"锦上添花"：网络抖动和限流是常态，没有它你的 Agent 会随机崩

**你要实现的契约**

```python
def chat(
    messages: list[dict],
    *,
    model: str | None = None,        # 默认取 settings.llm.model_chat
    temperature: float | None = None, # 默认取 settings.llm.temperature
    response_format: dict | None = None,
    tools: list[dict] | None = None,
    timeout_s: int | None = None,
) -> object:                          # 返回 message 对象
    """一次 LLM 调用：超时重试 → 失败转 LLMError → 返回 message。"""
```

**分步任务**

| 步 | 做什么                                                                                    | 自检方法                                  |
| - | -------------------------------------------------------------------------------------- | ------------------------------------- |
| 1 | 建 client：`OpenAI(base_url=settings.llm.base_url, api_key=settings.llm.chat_api_key())` | 不报错即可（还没发请求）                          |
| 2 | 最小 `chat()`：只传 model + messages，返回 `.choices[0].message`                               | 调一次，打印 `message.content` 能出中文         |
| 3 | 加超时：`timeout=settings.llm.timeout_s`                                                   | 故意把 timeout 设成 0.001，应抛超时异常           |
| 4 | 加重试：失败退避重试 `settings.llm.retry` 次，**重试前 sleep 递增**                                     | 断网跑一次，看到重试日志                          |
| 5 | 异常转化：`except Exception as e: raise LLMError(...) from e`                               | 填错 key，应看到 `LLMError` 而不是原始 traceback |
| 6 | 预留 trace 钩子（步骤 7 再实现）：`# TODO: write_trace(...)`                                       | 有 TODO 注释即可                           |
| 7 | 降级位：主力失败且配了 fallback → 用 `fallback_*` 再试一次                                             | 把主力 model 改成一个不存在的名字，应自动走降级           |

**掉坑提示**

- 火山方舟的 key 环境变量是 `ARK_API_KEY`，**没填会直接 `ConfigError`**（这正是我们设计的保护）
- `base_url` 末尾不要带 `/v1` 还是带？**以控制台给的为准**，错了会 404
- 豆包 turbo 支持 `response_format={"type": "json_object"}`，但**更推荐 W2 用 tools**，json_object 只是兜底
- 返回的 message 里 `tool_calls` 可能是 `None`，W2 判断时要用 `if not msg.tool_calls`

**过关自测**（三问）

1. 为什么这次返回 `message` 而不是 `message.content`？
2. 超时和重试的值从哪来？（答案：settings，不许硬编码）
3. 主力模型挂了会发生什么？

答得上来 → 步骤 4 通过；答不上来 → 回看本节「知识 3 分钟」。
