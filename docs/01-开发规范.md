# 01 · 开发规范（所有代码提交的硬性标准）

> 适用范围：本仓库全部 Python 代码、脚本、文档与 AI 协作产出。
> 配套：技术选型见 02，需求边界见 03，节奏见 04。规范之间冲突时以本文档为准。

## 1. 目录结构约定

```
kantoku-agent/
├── AGENTS.md            # AI 协作会话入口约束
├── README.md            # 项目门面（里程碑状态表必须保持最新）
├── docs/                # 全部规范与文档
├── config/              # settings.example.yaml（模板，事实来源）+ .env.example
├── src/kantoku/
│   ├── config/            # 公共基础设施：配置 + 异常 + 日志
│   │   ├── settings.py    # 配置加载（唯一读取配置的入口）
│   │   ├── errors.py      # 异常体系
│   │   └── logging_setup.py # 日志初始化
│   ├── core/              # llm.py（客户端）· tracing.py（埋点）· budget.py（预算）
│   ├── schemas/           # Pydantic 数据模型（分镜/质检/人设卡的契约）
│   ├── agent/             # loop.py 手写 ReAct 内核 · graph.py 状态机 · context.py 裁剪 · tools_registry.py
│   ├── tools/             # 分镜器/Prompt工厂/预算控制器/归档/台账
│   ├── perception/        # 截图 VLM 质检
│   ├── memory/            # 项目记忆 + 素材库混合检索
│   ├── shells/            # 可插拔交互层：cli.py（W1）→ gradio（可选）→ vtuber（W10 可选）
│   └── mcp_server.py      # 复用 tools/ 暴露为 MCP Server（W8）
├── tests/               # 与 src/ 镜像命名（tests/tools/test_storyboard.py）
├── evals/               # 评测集 JSONL + 评测说明
├── scripts/             # 一次性/维护脚本（run_eval.py 等）
├── data/                # 运行时数据（git 忽略）：SQLite、日志、下载
└── assets/              # persona/ 人设卡、demo/ 演示 GIF/视频
```

规则：业务逻辑只进 `src/kantoku/`；脚本只做编排；任何模块不得反向依赖具体里程碑之外未实现的模块。

## 2. 代码风格

- 工具链：ruff（检查 + 格式化），配置在 `pyproject.toml`；行宽 100；target py311。
- Python 版本：3.11–3.12；禁止使用 3.13+ 独有语法（保证底座与本地环境兼容）。
- 类型注解：公共函数/类必须完整注解；内部函数鼓励注解。
- 命名：模块/函数 `snake_case`，类 `PascalCase`，常量 `UPPER_CASE`；
  工具函数用动宾结构（如 `generate_storyboard`）。
- docstring：中文、Google 风格；每个模块首行 docstring 写清职责；
  注释只写"为什么/约束"，禁止写"这里改了什么"的流水账注释。
- import 顺序交给 ruff（规则组 I）；禁止 wildcard import。
- Windows 专项：路径一律 `pathlib.Path`；文件读写显式 `encoding="utf-8"`；行尾 LF。

## 3. 配置与密钥（红线）

- 模型名、端点、价格、预算、超时等一切可变参数**只允许**出现在 `config/settings.yaml`；
  代码只通过 `kantoku.config.get_settings()` 读取；禁止硬编码、禁止散落魔法数字。
- 密钥只存 `.env`（已被 `.gitignore` 排除），通过环境变量注入。
  代码、日志、文档、commit message、截图里出现真实密钥 = 立即作废该密钥并返工。
- `config/settings.example.yaml` 是配置结构的唯一事实来源：
  新增字段必须"先改模板 → 再改 `config.py` 模型 → 最后补测试"。

## 4. 错误处理与日志

- 异常体系（`kantoku/errors.py`）：`KantokuError` 基类 → `ConfigError` / `ToolError` /
  `BudgetError` / `UpstreamError`。新异常必须挂在这棵树上。
- 禁止裸 `except:`；捕获后必须（a）恢复或降级并向用户说明，或（b）包装后 re-raise。
- 外部调用（LLM/生图/HTTP）必须有超时与重试：默认 `timeout_s=30`、`retry=2`
  （生图类 60s），数值来自配置。重试用指数退避（2s/4s）。
- 日志用 loguru（`kantoku/logging_setup.py` 初始化）：控制台 + `data/logs/` 按天滚动，
  保留 14 天。日志禁止打印密钥与完整提示词正文（只打长度/摘要/哈希）。

## 5. 成本与安全红线（兼职生死的线）

- **任何付费调用（生图/图生视频）前必须过预算控制器**：
  `reserve(预估费用)` → 调用 → `settle(实际费用)`；
  超限抛 `BudgetError`，由 Agent 语音告知用户，而不是默默失败或默默烧钱。
- 每次付费调用写入台账：时间 / 工具 / 预估 / 实际 / 用途（关联集数与镜号）。
- 接单信息、剧本等个人内容只进 `data/`（git 忽略），不进仓库、不进文档。

## 6. 测试与评测

- 框架 pytest；`tests/` 与 `src/` 镜像命名。
- 工具函数必须有单测；涉及 LLM 的逻辑只测**编排与解析**（mock 网络调用），
  不测模型输出内容——模型效果交给评测（下条）。
- 质量评测：`evals/*.jsonl`，每行 `{"id","input","expect","rubric"}`；
  `scripts/run_eval.py` 输出 Markdown 报告到 `docs/evals/`；
  **每个里程碑打 tag 前必须跑一次并归档报告**。
- 收尾标准命令：`uv run ruff check . && uv run pytest`，任一红即未完成。

## 7. Git 与版本

- 分支：`main`（随时可运行）+ `feat/mX-主题` 任务分支，完成后合回 `main`。
- 提交信息：Conventional Commits，禁止一个 commit 混 feat 与 refactor：

  | 类型 | 用途 | 示例 |
  |---|---|---|
  | feat | 新功能 | `feat(tools): 分镜生成器支持时长校验` |
  | fix | 修缺陷 | `fix(budget): 每日额度跨天重置错误` |
  | docs | 文档 | `docs: 更新 M3 验收标准` |
  | refactor | 重构（行为不变） | `refactor(config): 合并读取逻辑` |
  | test / chore | 测试 / 杂务 | `chore: 升级 openai 依赖` |

- 里程碑完成：合入 `main` 并打 tag（v0.1.0 起，对应关系见 04），tag message 附演示文件名。
- 禁止对 `main` 使用 `--force`；禁止提交空 commit。

## 8. 文档与开发日志

- 每次开发结束更新 `docs/06-开发日志.md`（一行也行：日期/做了什么/坑）。
- 里程碑验收时同步更新 `README.md` 状态表。
- 规范变更走三步：提出 → 改 docs → 同一会话内实施；禁止口头改规范不落文档。

## 9. 依赖管理

- 仅通过 uv 增删依赖（`uv add` / `uv remove`），提交 `uv.lock`。
- 新增第三方依赖前必须先在 `docs/02` 的依赖登记表登记"用途/理由/里程碑"；
  能用标准库就不加依赖。
- 底座 Open-LLM-VTuber 独立目录运行，本仓库不把它装进依赖。

## 10. AI 协作规范（ZCode / Claude 等）

- AI 会话入口永远是 `AGENTS.md`；AI 只做当前里程碑范围内的任务。
- AI 产出代码同样适用本规范；提交前必须通过 ruff + pytest。
- AI 不得实现"明确不做"清单中的功能；不得自行升级/更换底座。
- AI 改规范类文档前需先向用户确认，再改文档，再动代码。
