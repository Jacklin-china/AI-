# 04 · 开发流程与里程碑计划 v2（10 周，2026-09 修订）

> 本版取代原六周计划。修订依据见 `docs/08-竞争力评审与架构计划优化.md`。
> **开工前先读 `docs/10-系统全景与功能说明书.md`**——它用一次完整使用讲清了全流程，
> 本文件则是把它拆成每周可执行的步骤。
> 每个步骤用到的知识点编号（K0–K14）对应 `docs/09-学习路线与视频清单.md`。
> **看完视频 → 立刻做本文件里对应的步骤**，这是"学以致用"的唯一通道。

## 0 · 防烂尾五条铁律（先看这个）

| # | 铁律 | 具体做法 |
|---|---|---|
| 1 | **演示即验收** | 没有 1 分钟演示 = 里程碑未完成。演示**当天录**，不攒、不补拍。 |
| 2 | **MVP / 增强分档** | 每个里程碑拆两档。时间不够只交 MVP，**里程碑照样算过**。增强档不做不扣分。 |
| 3 | **止损线硬执行** | 任一卡点超过下表时限，立即停手走降级方案，不许硬扛。 |
| 4 | **周日 15 分钟自检** | 每周日回答三个问题（见 §12），连续两周无产出 → 强制砍增强档 + 缩减范围。 |
| 5 | **先跑通再优化** | 任何模块先用最笨的方式跑通一次，再谈优化。禁止"边写边重构"。 |

**为什么这么设计**：新手烂尾的头号原因不是技术难，是**在前置依赖上耗光预算**（底座、环境、全家桶教程）。所以本计划把风险最高的东西全部后置，把"能最快看到成果"的东西前置。

## 2 · W1 · M0 地基（20h）

**目标**：不碰任何 UI / 语音 / 底座，只要一条能跑通的 headless 链路。

| 步骤 | 做什么 | 知识点 | 产出 |

| 2 | 建目录骨架（按 01 §1 + 08 §C2） | — | `src/kantoku/` 空包 |
| 3 | `config.py` + `errors.py` + `logging_setup.py` | K1 | 配置从 yaml 读，异常挂树 |
| 4 | `core/llm.py`：OpenAI 兼容客户端（超时 + 重试 + 降级） | K1 | 超时/重试走 config |
| 5 | **`schemas/storyboard.py`：pydantic 定义 + 解析 LLM JSON** | **K1** | `Storyboard` 模型；解析失败打印原始返回 |
| 6 | **核对控制台实际模型名**（GLM-4.6 / GLM-4.6V） | K1 | 02 文档同步更新 |
| 7 | `core/tracing.py`：trace 表落库 | K9 | 每次调用一条 trace |
| 8 | `shells/cli.py`：命令行一句问答 + 结构化输出 | K0 K1 | 能打字能回，能吐 JSON |

- **验收**：`uv run ruff check . && uv run pytest` 全绿；CLI 对话 5 轮并打印 trace 摘要；**`Storyboard` 模型解析成功且有失败用例的单测**。
- **演示**：终端里跟"监督酱"文字对话 + 展示 trace 记录。
- **止损**：环境配置 >1 天 → 放弃本地折腾，直接 `uv run` + 云 API，环境问题后置。

> **K1 视频 → W1 步骤对照**（吴恩达 Pydantic 结构化输出全集约 40 min）

## 12 · 周日自检（15 分钟，防烂尾的核心动作）

每周日回答三个问题，写在 `docs/06-开发日志.md`：

1. **这周有没有产生一个能演示的东西？**（有 / 没有）
2. **卡在哪一步，卡了多久？**（超过止损线了吗）
3. **下周的 MVP 是什么？**（必须是一句话能说清的东西）

**连续两周"没有" → 强制动作**：
- 砍掉当前里程碑的所有增强档；
- 把剩余范围砍到能在 5 小时内完成；
- 如果还是做不完 → **跳过该里程碑，直接进下一个**。（跳过的写进 06 日志，未来补。）

## 13 · 砍功能时的竞争力保护清单

砍东西不可避免，但**每砍一样，必须用别的方式补回关键词**，否则竞争力会掉：

| 如果砍掉 | 会损失 | 必须补上 |
|---|---|---|
| MCP（W8） | JD 高频词 | 至少在 README 写清"工具层按 MCP 协议设计，可一键封装" |
| 状态机（W7） | LangGraph 关键词 | 至少保留 `langgraph-mapping.md` 文档 |
| 向量检索（W6） | RAG 关键词 | 保留 FTS5 + 写清"何时不需要向量"的判断依据 |
| VLM 打分（W5） | 多模态关键词 | 保留 2 个二元判定，够证明能力 |
| VTuber 外壳（W10） | 人设交互亮点 | 用 CLI + 人设卡文案演示，影响很小 |
| 真实接单（W9） | **生产级背书（损失最大）** | 至少自做 1 集并填 05 表，**这条别砍** |
