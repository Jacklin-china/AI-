KANTOKU · 监督酱 — 界面设计方案 v2

把创作入口收敛成一个输入框，
把结果摆成可以挑的样子

参考小云雀与既梦的交互范式，针对「本地 AI 漫剧生产工作台」的真实能力做转译。不新增伪功能，不伪造生成结果——所有改动都落在现有数据与接口能支撑的范围内。

一 · 从两家产品提炼的四个范式

可迁移的部分

小云雀与既梦形态不同（前者移动端对话流，后者 PC 左右分栏），但有四个共同决策。它们就是这次升级的骨架。

1 · 单一输入框驱动

所有创作从一个输入框开始。模型、尺寸、数量这些参数不另开面板，而是内嵌在输入区底部，随手写随时改。用户不需要先"配置"再"创作"。

2 · 灵感模板可一键做同款

首页不只有输入框，下方是模板流。看到喜欢的直接套用，把"从零描述"降级为"改一点点"。这是降低门槛最有效的一环。

3 · 结果并排，供挑选

生成不是终点，挑选才是。结果以网格并排呈现，配「重新编辑 / 再次生成」，让"不满意"有明确出口。

4 · 左侧导航带最近创作

历史创作记录直接挂在导航里，回来就能接着改，而不是先进"资产库"再翻找。

本次取舍：你选择保留现有导航（不重构信息架构），因此范式 4 只做视觉升级；范式 1、2、3 完整落地。

二 · 字体

单一字族，靠字号与字重拉开层级

上一版首页标题用了衬线体（Source Han Serif）。小云雀、既梦都是无衬线、字重对比强烈的现代中文界面——衬线体来自另一份参考稿，与这次方向不符，所以撤掉，改为全局单一无衬线字族。

字族

"PingFang SC", "HarmonyOS Sans SC", "MiSans", "Source Han Sans SC", "Noto Sans SC", "Microsoft YaHei", Inter
中文优先取系统高质量黑体，西文回落 Inter。不引入 Web Font——本地工具应当秒开，不依赖网络。

字号阶梯

Hero描述你要做的这一镜28 / 600 / -.025em
页面标题任务与运行21 / 600
区块标题生产流水线16 / 600
正文让 AI 创作可控、可追溯、可规模化14 / 400 / 1.6
控件开始创作13 / 500
辅助信息Studio · 图片生产 · 03-14 21:4012 / 400

层级靠字号 + 字重 + 颜色三重落差，而不是靠给标题加 ALL-CAPS 小标签。同时去掉表格表头的全大写与宽字距——那是模板味很重的处理。

四 · 圆角与尺寸

按层级分配，不再统一一个值
Token值用于
--radius-control6px → 8px按钮、输入框、选择器
--radius-card14px → 16px卡片与面板
--radius-composer22px（新）首页输入卡——全局唯一的大圆角，是整页的记忆点
--radius-tile3px → 4px资产瓦片（密集图墙，近直角）
--radius-pill999px胶囊、徽章、分段控件

原则：越靠近输入动作，圆角越大。输入卡 22px 是最大值，往下逐级收敛到瓦片的 4px。这样层级是能"摸"出来的。

五 · 按钮与控件

五个层级 × 三种尺寸

现有 .ui-button 只有一个实心样式加一个 primary，靠 kbd 子元素临时拼装。改为完整的层级体系，所有状态（悬停 / 按下 / 禁用 / 加载 / 聚焦）都有定义。

层级

Primary 一个视图里最多一个，是页面唯一想让你按的按钮。  Secondary 白底发丝边，用于并列动作。  Quiet 无边框，hover 才出现底色，用于取消类低频动作。

尺寸

高 42 / 34 / 28。默认 34，输入区的主行动用 42——手指和视线都先落在大按钮上。

状态

按下时整钮下沉 1px（translateY），不只变颜色。加载态保留按钮宽度，避免布局跳动。

图标按钮

胶囊与分段控件

胶囊用于多选/单选参数（模型、能力、模板），分段控件用于互斥视图切换。两者不可混用——这是既梦和小云雀都守住的一条。

六 · 输入卡（Composer）

整页唯一的大动作

这张卡是这次改版的记忆点：22px 圆角、淡投影浮起、参数内嵌底部。其他所有元素都保持克制，把注意力让给它。

参数做成胶囊直接长在输入区里，改模型/比例不需要离开输入框。聚焦时外圈加 3px 强调色光环，明确告诉用户"光标在这里"。

七 · 首页布局

对话式入口 + 灵感模板流
最近创作
问候语 + 一句话说明

自上而下：问候 → 输入卡 → 灵感模板流（4 列网格，可横向滚动）→ 继续创作（最近的真实 Run）。右侧的流水线 / 待办栏保留。

八 · 结果挑选

按真实能力做，不伪造第四张

既梦一次出 4 张是因为接口支持批量。你的 settings.yaml 里 quantity 硬锁为 1（"1 · 当前真实接口"），所以不做假的 2×2 四选一。真实做法是：

  • 同一 project + 镜号的每一次成功生成都是一个候选，按时间加入结果网格
  • 网格列数自适应真实候选数：1 张居中大图，2 张并排，3–4 张 2×2，更多则按 auto-fill 铺满
  • 选中某张 → 该 Run 成为当前产物，进入质检 / 审批 / 归档
  • 网格下方常驻 重新编辑 与 再次生成；"再次生成"产生的新图自动追加为下一个候选

选中态：2px 强调色描边 + 右上角对勾。候选数 = 真实生成次数。

九 · 交互与动效

只响应用户动作
场景处理
按钮按下下沉 1px，120ms
卡片悬停抬起 1px + 阴影加深，不放大不变色
瓦片悬停图片放大 1.05，底部渐变信息条淡入
键盘聚焦2px 强调色描边 + 2px 偏移，全站统一
生成中按钮内嵌转圈，保留原宽度
结果出现淡入 + 轻微上移，只此一次，不做逐项错峰

不做非用户触发的常驻动画。首页保留打字机问候（它已在代码中，是品牌的一部分），但不给每个区块加入场动画——那会让工具显得轻浮。
